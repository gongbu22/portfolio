### 3. 주요 어려움 및 해결 과정


#### 3-1. 운영 초기 실시간 데이터 오류 분석 및 대응 체계 개선

**경험 및 어려웠던 점**

- 초기 운영 과정에서 실시간 데이터 오류가 빈번하게 발생함. 
- 2주가 지난 과거 데이터의 오류는 OpenSearch에 로그가 남아있지 않아서 원인 파악이 어려웠음.
- 특히 결재, 후처리 등 업무 흐름과 데이터 간의 연관 관계를 파악해야 오류 처리를 할 수 있는 부분이 많았음.

**해결 과정**

- OpenSearch 로그와 소스코드를 확인하면서 오류 발생 시점과 원인을 추적함
- 로그가 남아있지 않은 과거 오류는 관련 소스코드와 데이터 테이블을 하나씩 확인하면서 원인 분석함
- 반복적으로 발생하는 오류와 주요 확인 사항을 문서화하여 이후 유사 사례에 효율적으로 대응할 수 있도록 정리함
- 프로세스 파악이 어려운 경우 현업 담당자와 소통하면서 실제 처리 흐름을 확인함

**배운 점**

- 오류 원인을 정확하게 파악하기 위해서는 로그 뿐만 아니라 소스코드와 데이터의 흐름, 업무 프로세스까지 함께 이해해야 한다는 것을 배웠습니다.
- 다양한 유형의 데이터 오류에 효율적으로 대응하기 위해서는 오류 유형과 해결 과정을 문서화하는 것이 중요하다는 점을 배웠습니다
- 현업 담당자와의 소통을 통해 실제 업무 프로세스를 정확하게 파악하는 것이 문제 해결에 중요하다는 점을 경험했습니다.


### 3-2. SAP API 연계 과정에서의 데이터 검증 및 담당자 간 소통

**경험 및 어려웠던 점**

- ITAM에서 일부 자산 관련 품의서를 생성하는 과정에서 SAP 결재 API 연계가 필요했음.
- 인터페이스 정의서에 필수 요청 파라미터와 요청,응답 데이터 예시가 충분히 명시되어 있지 않아 API 호출에 필요한 정보를 파악하기 어려웠음.
- 개발,품질,운영 환경 별 SAP 데이터와 ITAM 시스템 자산 데이터가 서로 달라서 동일한 조건으로 API 호출 테스트가 어려웠음.
- SAP 호출 에러 관련 정의된 문서도 없어서 원인 판단 및 후속처리에 어려움이 있었음

**해결 과정**

- OpenSearch 로그를 통해 SAP API 호출 시 발생한 오류와 응답 내용을 확인하며 원인 추적함
- 오류 발생 시 요청데이터와 응답데이터를 정리해서 현업담당자를 통해 SAP 담당자에게 확인 요청 후 처리함
- SAP 호출 테스트가 어려운 환경에서는 정상 응답 형태의 JSON 데이터를 구성해 테스트에 활용하고, 응답 데이터에 따른 Java 후처리 로직 수정함


**배운 점**

- 인터페이스 정의서와 오류 관련 문서에 API 호출 정보 및 처리 기준을 정확하게 기록하고, 오류 발생 시 해당 문서를 활용해 원인을 파악하는 것이 중요하다는 점을 배웠습니다.
- API 호출에 필요한 정보와 처리 기준을 확인하기 위해 현업 담당자 및 SAP 담당자와 원활하게 소통하는 것이 중요하다는 점을 배웠습니다.
- 오류 발생 시 로그와 관련 데이터를 먼저 확인해 문제 상황을 정리하고, 확인이 필요한 내용을 담당자에게 구체적으로 전달하는 것이 원인 파악에 도움이 된다는 점을 경험했습니다.
